암호화된 트래픽, 내용은 못 봐도 앱은 맞힌다

요즘 트래픽은 거의 다 TLS·QUIC로 암호화돼 있어서 패킷 안을 들여다볼 수 없어요. 대신 패킷의 크기·방향·간격은 그대로 보여요. 유튜브, 카톡, 게임, 웹서핑은 이 모양이 서로 달라서, 그 "지문"만으로 머신러닝이 앱을 구분하게 만드는 프로젝트예요.

플로우 하나의 지문

앱을 골라 보세요. 막대 하나가 패킷 하나예요. 위로 솟으면 내가 보낸 것(업로드), 아래로 내려가면 받은 것(다운로드)이고, 길이가 패킷 크기예요.

업로드 ↑ (클라이언트 → 서버) 다운로드 ↓ (서버 → 클라이언트)
모델에 들어가는 값 중 일부: 첫 10개 패킷의 부호 있는 크기 (first_0 … first_9)

예시 그림은 scripts/make_synthetic.py의 가상 프로필로 만든 거예요. 실제 앱 트래픽은 직접 캡처해서 확인해야 해요.

코드가 하는 일, 4단계

  1. 캡처하기

    src/capture.py

    앱 하나만 켜 두고 몇 분 동안 트래픽을 녹화해요. 폴더 이름이 곧 정답 라벨이 돼요.

    python -m src.capture --label youtube --duration 180 --iface "Wi-Fi"
→ data/raw/youtube/youtube_20261117_143000.pcap

  2. 플로우로 묶고 특징 뽑기

    src/flows.py · src/features.py

    패킷을 플로우 단위로 묶어요. 플로우는 "같은 두 컴퓨터, 같은 포트, 같은 프로토콜"끼리 주고받은 패킷 묶음(5-tuple)이에요. 너무 긴 플로우는 30초씩 잘라서 샘플 수를 늘려요. 그다음 플로우마다 숫자 약 40개를 계산해 CSV 한 줄로 만들어요.

    python -m src.features --raw data/raw --out data/features.csv

  3. 학습하고 채점하기

    src/train.py

    RandomForest로 학습하고(XGBoost를 깔면 같이 비교), 정확도·macro-F1·혼동행렬·중요한 특징 순위를 출력해요. 제일 좋은 모델을 저장해요.

    • 캡처 파일 단위로 시험: 앱마다 캡처 파일 일부를 통째로 빼서 시험용으로 써요. 같은 녹화에서 나온 플로우가 학습·시험 양쪽에 섞이면 점수가 부풀려지거든요.
    • --no-port: 포트 번호를 빼고도 학습해 봐요. 그래도 맞히면 "포트가 아니라 트래픽 모양으로 구분한다"는 근거가 돼요.
    python -m src.train --data data/features.csv --model models/model.joblib

  4. 실시간 데모

    src/live_demo.py

    지금 흐르는 트래픽을 몇 초마다 잡아서 플로우별로 "어떤 앱인지, 몇 % 확신하는지" 보여줘요. 최종 발표 시연용이에요.

    14:32:07 ------------------------------------------------------------
  UDP              142.250.196.110:443    1832 pkts  ->  youtube      94%
  TCP                 211.249.220.24:443     41 pkts  ->  kakaotalk    81%
  UDP                  52.79.12.200:7777    905 pkts  ->  game         88%

    출력 모양 예시예요. 숫자는 실제 결과가 아니에요.

모델이 보는 숫자들

전부 패킷 헤더에서 나오는 정보라서 암호화와 상관없이 계산돼요.

묶음예시 특징왜 도움이 되나
양n_up, n_down, bytes_up, bytes_down영상은 받는 양이 압도적, 게임은 주고받는 양이 비슷해요.
크기 통계size_mean, up_size_std, down_size_max영상은 1,300바이트 넘는 꽉 찬 패킷, 채팅은 작은 패킷이 많아요.
시간 간격iat_mean, iat_std, iat_max게임은 일정한 박자로, 채팅은 띄엄띄엄 보내요.
속도pkts_per_sec, bytes_per_sec, down_up_byte_ratio스트리밍과 메시지를 가르는 가장 큰 차이예요.
첫 10개 패킷first_0 … first_9연결 초반 주고받는 패턴이 앱마다 달라요. 실시간으로 빨리 판단하는 데 좋아요.
프로토콜·포트proto, server_portQUIC(UDP 443)이냐 게임 전용 포트냐. --no-port로 뺄 수 있어요.
